## 1. Цель

Заменить текущий одностраничный сайт на конструкторе Megagroup лёгким, быстрым и **продающим** сайтом в фирменном стиле INTEKKO, который:

1. За 5 секунд объясняет, кто такие INTEKKO: аккредитованный центр RoSPA (№223) и IOSH (№5072), аттестат МЧС РК, тренинги по HSE и безопасному вождению по всему Казахстану.
2. Помогает HR-специалисту или специалисту по ТБ найти нужный курс **не больше чем за 3 клика**: направление → курс → заявка.
3. Показывает **график ближайших открытых курсов** и даёт записаться на конкретную дату в один клик.
4. Собирает заявки и **автоматически создаёт лиды в Bitrix24**: с курсом, датой, UTM-метками и страницей, с которой пришла заявка.
5. Индексируется поисковиками: у ключевых курсов отдельные страницы, есть HTTPS, schema.org и sitemap.

**Бизнес-метрики (цели на 3 месяца после запуска):**

| Метрика | Цель |
|---|---|
| Конверсия посетителя в заявку (форма + клик по телефону или WhatsApp) | ≥ 3 % |
| Доля заявок, попавших в Bitrix24 без ручного ввода | 100 % |
| Lighthouse Performance / SEO / Accessibility (мобильная версия) | ≥ 90 / ≥ 95 / ≥ 90 |
| Вес главной страницы при первой загрузке | ≤ 1 МБ |
| Время на обновление графика (менеджер, без программиста) | ≤ 5 минут |

## 3. Анализ текущего сайта (AS-IS)

| Параметр | Текущее состояние | Проблема |
|---|---|---|
| Платформа | SaaS-конструктор **Megagroup** (S3), хостинг Megagroup, nginx | Закрытая платформа: нельзя добавить свою интеграцию с Bitrix, свой график или нормальные страницы курсов |

| Структура | Фактически одна страница: `/`, `/kontakty`, `/user` | Нет страниц курсов, поэтому нечего индексировать по запросам «курс ПромБез Астана» и подобным |
| Формы | 2 формы (телефон; имя + телефон + комментарий), Yandex SmartCaptcha | Не указан курс, нет передачи в CRM |
| Ссылки | Шапка: `tel:+77085550123` (верно). Блок контактов: `tel:+70085550123`, `wapp.click/+70085550123`, `tel:+70085550128`, `wapp.click/+70085550128` | **Ошибки в номерах:** выпала цифра 7 (`+7 008…` вместо `+7 708…`), ссылки на звонок и WhatsApp из блока контактов не работают. | Аналитика | Яндекс.Метрика, счётчик Megagroup, онлайн-чат Onicon | Метрику сохраняем, остальное убираем |
| Языки | Только RU | — |

### 5.3 График курсов (по референсу со скриншота)

**Расположение:** блок на главной (5–7 ближайших строк) и отдельная страница `/schedule/` с полным графиком.

**Структура (как на скриншоте, но в фирменной палитре):**
- Надзаголовок «ГРАФИК КУРСОВ», заголовок «Ближайшие открытые курсы», подзаголовок «Выберите программу, страну, город и формат. По запросу организуем корпоративную группу».
- **Таблица (десктоп):** Курс (ссылка на страницу курса) · Даты (иконка календаря, «12–14 октября 2026 г.», «26 октября – 6 ноября 2026 г.») · Страна · Город (иконка метки; для онлайна «Дистанционно») · Формат (Очный класс / Виртуальный класс / Дистанционно (Teams)) · Статус (бейдж) · **кнопка «Записаться»**. Кнопки нет на скриншоте, но она главный элемент продаж.
- **Бейджи статуса:** `Набор открыт` (зелёный, единственное допустимое использование зелёного), `Мало мест` (красный), `Планируется` (синий), `Набор закрыт` (серый, кнопка неактивна).
- **Мобильная версия:** таблица превращается в карточки (курс, даты, город и формат одной строкой, бейдж, кнопка во всю ширину). Горизонтального скролла нет.
- **Фильтры (на `/schedule/`):** направление, курс, город, формат, месяц. Сброс фильтров. Фильтры отражаются в URL (`?city=astana&format=online`), чтобы ссылкой можно было поделиться.
- **Автоматика:** прошедшие даты скрываются автоматически, сортировка по дате начала. Если подходящих курсов нет: «Ближайших дат пока нет — оставьте заявку, сообщим о наборе».
- **Под таблицей:** два блока, как на скриншоте. Слева карточка **«Нужна другая дата?»** («Оставьте заявку, и мы предложим даты для вашей команды, включая другой город или страну») с кнопкой «Все курсы». Справа **форма заявки**.
- **«Записаться»** открывает модальную форму, где уже выбран курс и подставлены дата и город (скрытые поля `schedule_id`, `course_slug`).
- Разметка schema.org `CourseInstance` для каждой даты.

**Источник данных:** Google Таблица (см. раздел 8.2).

### 5.4 Форма заявки + интеграция с Bitrix24

**Поля:**

| Поле | Тип | Обязательно | Примечание |
|---|---|---|---|
| Имя | text | ✔ | 2–80 символов |
| Компания | text | — | |
| Телефон | tel | ✔ | Маска `+7 (___) ___-__-__`, проверка формата KZ |
| Email | email | — | Проверка формата |
| Курс или услуга | мультивыбор (чипы-чекбоксы, как на скриншоте) + поиск по каталогу | — | Подставляется автоматически, если форма открыта со страницы курса или из графика |
| Количество участников | number / выбор (1, 2–5, 6–15, 16+) | — | Помогает отличить B2B от физлица |
| Предпочтительный формат | выбор: Очно в центре / Выезд к нам / Онлайн / E-learning | — | |
| Сообщение | textarea | — | До 1000 символов |
| Согласие на обработку ПДн | checkbox | ✔ | Ссылка на `/privacy/` (Закон РК «О персональных данных и их защите») |
| Скрытые | hidden | — | `schedule_id`, `course_slug`, `page_url`, `utm_source/medium/campaign/term/content`, `referrer` |

**Поведение:**
- Проверка полей на лету, понятные сообщения об ошибках на русском.
- Защита от спама: honeypot-поле + **Yandex SmartCaptcha** в невидимом режиме (уже используется на текущем сайте) + ограничение частоты запросов на сервере (не больше 5 заявок с одного IP за 10 минут).
- После отправки: переход на `/thanks/` (или сообщение в модальном окне): «Спасибо! Мы свяжемся с вами в течение рабочего дня» + кнопка WhatsApp.
- Цели в Яндекс.Метрике: `form_submit`, `schedule_signup`, `click_phone`, `click_whatsapp`, `click_email`.

**Интеграция с Bitrix24 (серверная):**
- Форма отправляет `POST /api/lead.php` (JSON). **Адрес вебхука Bitrix хранится только на сервере** (`config.php` или переменная окружения вне webroot) и никогда не попадает в браузер.
- `lead.php` проверяет данные и капчу, затем вызывает входящий вебхук Bitrix24, метод `crm.lead.add`:
  - `TITLE`: «Заявка с сайта: <курс> [<дата>, <город>]» или «Заявка с сайта: консультация»
  - `NAME`, `COMPANY_TITLE`, `PHONE: [{VALUE, VALUE_TYPE: "WORK"}]`, `EMAIL: [{VALUE, VALUE_TYPE: "WORK"}]`
  - `COMMENTS`: сообщение + выбранные курсы + количество участников + формат + страница-источник
  - `SOURCE_ID: "WEB"`, `SOURCE_DESCRIPTION: page_url`
  - `UTM_SOURCE`, `UTM_MEDIUM`, `UTM_CAMPAIGN`, `UTM_CONTENT`, `UTM_TERM`
  - Пользовательские поля (создаются в Bitrix, коды уточняются): `UF_CRM_COURSE`, `UF_CRM_SCHEDULE_DATE`, `UF_CRM_CITY`, `UF_CRM_PARTICIPANTS`
  - `ASSIGNED_BY_ID`: ответственный менеджер (настройка в конфиге)
- **Запасной канал:** если Bitrix вернул ошибку или не ответил за 5 секунд, заявка уходит письмом на sales@intekko.kz (SMTP) и пишется в серверный лог `leads-failed.log` (не в webroot). Пользователь в любом случае видит «Спасибо».
- **Тестовый режим:** `BITRIX_DRY_RUN=true` — лид не создаётся, payload пишется в лог.
- Адаптер Bitrix вынесен в отдельный модуль, чтобы при переходе на коробочный «1С-Битрикс» поменять только URL и формат вызова.

### 5.5 Каталог курсов `/courses/`

### 8.2 График — Google Таблица (обновляет менеджер)

**Лист `schedule`** (первая строка — заголовки, менеджер заполняет строки):

| Колонка | Пример | Правило |
|---|---|---|
| `id` | 2026-11-iosh-ast | Уникальный |
| `course_slug` | iosh-managing-safely | Выпадающий список из листа `courses` (валидация данных) |
| `start_date` | 2026-11-25 | Дата |
| `end_date` | 2026-11-27 | Дата ≥ start_date |
| `country` | Казахстан / Онлайн | Список |
| `city` | Астана / Алматы / Дистанционно | Список |
| `format` | Очный класс / Виртуальный класс / Дистанционно (Teams) | Список |
| `language` | RU / KZ / EN | Список |
| `status` | open / few_seats / planned / closed | Список |
| `seats_left` | 4 | Необязательно |
| `note` | | Необязательно |
| `published` | TRUE | Только TRUE попадает на сайт |

**Как данные попадают на сайт:**
1. Лист публикуется как CSV («Файл → Опубликовать в интернете»). Ссылка хранится в конфиге сервера.
2. `GET /api/schedule.php` скачивает CSV, проверяет и нормализует строки, отбрасывает прошедшие и неопубликованные, возвращает JSON. **Кэш на сервере 15 минут**; если Google недоступен, отдаётся последняя удачная копия.
3. При сборке сайта делается снимок графика и встраивается в HTML: страница сразу показывает данные, их видят поисковики, есть schema.org. После загрузки страницы график обновляется из `/api/schedule.php`.
4. Ошибочные строки (нет даты, неизвестный `course_slug`) пропускаются и пишутся в лог. Сайт из-за них не ломается.
5. **Инструкция для менеджера** (1 страница) входит в состав поставки: как добавить дату, сменить статус, скрыть строку.

## 9. Технический стек и архитектура

**Решение:** статический сайт на **Astro** + два PHP-обработчика + казахстанский виртуальный хостинг.

| Слой | Технология | Почему |
|---|---|---|
| Генератор сайта | **Astro 5** (SSG), TypeScript | На выходе чистый HTML без лишнего JS: быстро и хорошо для SEO. Компоненты переиспользуются. Встроенная i18n для KZ/EN |
| Стили | Tailwind CSS 4 с токенами из 6.1 (или vanilla CSS + custom properties) | Быстрая вёрстка, единые токены |
| Интерактив | Островки на чистом TS / Alpine.js: фильтры, модалка, маска телефона, поиск | Без React, минимальный размер JS |
| Поиск | Fuse.js по JSON-индексу курсов | Работает на клиенте, без сервера |
| Бэкенд | PHP 8.2: `api/lead.php`, `api/schedule.php` | Есть на любом хостинге в РК, без отдельного сервера |
| Хостинг | **hoster.kz**, виртуальный хостинг. Требования к тарифу: PHP ≥ 8.1 с `curl`, `json`, `mbstring`; бесплатный SSL (Let's Encrypt) с автопродлением; FTP/SFTP (лучше SSH); cron; хранение файлов вне webroot; отправка почты по SMTP; `.htaccess` (Apache) или настройка редиректов в панели | Решение заказчика. Данные заявок (ПДн) хранятся в РК, низкая задержка для пользователей в Казахстане |
| Репозиторий и деплой | GitHub (приватный) → GitHub Actions: `astro build` → выгрузка `dist/` на hoster.kz по SFTP (или FTPS), только изменённые файлы. Пересборка по расписанию раз в сутки (снимок графика). Доступы к хостингу хранятся в GitHub Secrets | Контроль версий; кнопка «Пересобрать» для менеджера (ручной запуск workflow) |
| Аналитика | Яндекс.Метрика (переносим текущий счётчик) + Google Analytics 4 (опционально) | Цели из 5.4 |
| Капча | Yandex SmartCaptcha (невидимая) | Уже используется заказчиком |

**Почему не остаёмся на Megagroup:** закрытый конструктор не даёт сделать серверную интеграцию с Bitrix через вебхук (ключ пришлось бы держать в браузере), график из Google Таблицы, страницы курсов из одного шаблона и нормальный HTTPS. Сейчас на сайте невалидный сертификат.

**Структура репозитория:**
```
intekko-site/
├─ PRD.md
├─ assets/logo/       # исходные логотипы (SVG/PNG), копируются в public/
├─ public/            # favicon, robots.txt, шрифты, изображения, api/*.php (копируются как есть)
│  └─ api/
│     ├─ lead.php
│     ├─ schedule.php
│     └─ lib/ (bitrix.php, mailer.php, validate.php, ratelimit.php)
├─ config/            # config.example.php (без секретов), секреты лежат на сервере вне webroot
├─ src/
│  ├─ data/courses.json, site.json (контакты, цифры), schedule.snapshot.json
│  ├─ i18n/ru.json    # все UI-строки (заготовки kk.json, en.json)
│  ├─ components/     # Header, Footer, Hero, StatCards, DirectionCard, ScheduleTable, LeadForm, Modal...
│  ├─ layouts/
│  └─ pages/          # index, courses/[...], schedule, consulting, about, contacts, privacy, thanks, 404
├─ scripts/fetch-schedule.mjs  # снимок графика при сборке
└─ docs/manager-guide.md
```

**Безопасность:**
- Секреты (вебхук Bitrix, SMTP, ключ капчи) лежат только на сервере вне webroot и не попадают в Git (`.gitignore`, `config.example.php`).
- Проверка данных на сервере, экранирование, ограничение размера запроса, CORS только для своего домена, ограничение частоты запросов.
- HTTPS + HSTS, заголовки CSP, X-Frame-Options, Referrer-Policy.
- Логи заявок не лежат в публичной папке; срок хранения логов с ПДн — 30 дней.
